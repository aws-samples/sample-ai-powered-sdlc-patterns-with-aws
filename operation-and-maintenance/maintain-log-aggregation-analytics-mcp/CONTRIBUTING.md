# Contributing Guidelines

Thank you for your interest in contributing to this project. Whether it's a bug report, new feature, correction, or additional documentation, your feedback and contributions are welcome.

## Reporting Bugs / Feature Requests

Use GitHub Issues to report bugs or suggest features. When filing an issue, please check existing issues to avoid duplicates and include as much information as possible:

- A reproducible test case or series of steps
- The version of the code being used
- Any relevant logs or error output
- Any modifications you've made

## Security Issue Notifications

If you discover a potential security issue, please notify AWS Security via the
[vulnerability reporting page](https://aws.amazon.com/security/vulnerability-reporting/).
Please do **not** create a public GitHub issue for security vulnerabilities.

## Contributing via Pull Requests

1. Fork the repository
2. Create a feature branch from `main`
3. Make your changes, ensuring:
   - Code follows existing style and conventions
   - Input validation is applied to any new user-facing parameters
   - AWS API calls include proper error handling
   - Sensitive data is sanitized before external transmission
4. Test your changes locally
5. Submit a pull request against `main`

Pull requests should:
- Focus on a single change
- Include a clear description of the problem and solution
- Reference any related issues
